# codemap v2 — Plan 3: Evals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure the two anti-goals (off-path nodes, splits that disagree with the code) on codemap's own trace pipeline. Measure the verifier's real-hop rejection rate. Record cost and time on the smoke repos.

**Architecture:** An `evals/` folder outside the package. It has hand-reviewed expected files, a pure scorer, and runners that call `Service` with the configured model and record calls through `JsonFileCache` (Plan 1 Task 6), so a re-score replays with no API cost.

**Tech Stack:** Python, pytest (scorer unit tests), the codemap package.

**Spec:** `docs/specs/2026-10-17-codemap-v2-design.md` (§11).

**Depends on:** Plan 1 complete. Plan 2 is not needed.

## Global Constraints

- The code is ground truth, not docs. Expected files are written by reading code at a pinned commit.
- Expected shape for codemap: phases follow the code's execution units (the CLI command, then each pipeline stage). Resolve, walk and split are steps inside one phase when they run in one function.
- The user reviews each expected file once before it is used for scoring.
- Evals never run in `make check`. They run with `make eval`.
- Target repos: codemap itself (relative path `.`) and `tests/fixtures/sample_repo`. Users add their own repos to `evals/smoke.json`.

## Review Focus

1. **The target working tree has moved past the pinned commit** → the runner refuses to run and names the pinned and current sha. An empty `commit` skips the check. (Task 2)
2. **An expected file references a path that no longer exists** → the scorer fails loudly when it loads the file, not later with a silent zero. (Task 1)
3. **A recorded replay is missing a call** → the run fails with `ModelError("no recording")` and does not silently call the API. (Task 2)
4. **A trace ends `partial`** → its scores are still computed and reported with the status beside them. (Task 2)
5. **Verifier hop set from a repo with no git** → hop anchors are resolved with content hashes, not shas. (Task 3)

### Task 1: Expected-file format and scorer

**Files:**
- Create: `evals/__init__.py`, `evals/expected.py`, `evals/score.py`
- Test: `evals/tests/test_score.py`

**Interfaces:**
- Produces:
  - `ExpectedTrace(repo: str, commit: str, question: str, entry: Anchor, phases: list[ExpectedNode], effects: list[ExpectedEffect])`, with `ExpectedNode(title: str, spans: list[Anchor], steps: list[ExpectedNode] = [])` and `ExpectedEffect(category, target, op)` (pydantic). `load_expected(path: Path, repo_root: Path) -> ExpectedTrace` checks that every span file exists, and raises `ValueError` naming the missing path.
  - `score(graph: TraceGraph, expected: ExpectedTrace) -> Score`. `Score` holds:
    - `off_path_nodes: int`: nodes with no anchor overlapping any expected span at any level.
    - `phase_agreement: float`: a greedy one-to-one match of phases by best line-overlap ratio. It is the mean IoU of matched pairs × matched count ÷ max(len(actual), len(expected)).
    - `step_agreement: float`: the same, computed inside each matched phase and then averaged.
    - `effect_recall: float`: expected effects found, matched on `(category, target, op)`.
    - `effect_extra: int`.
    - `status: str`.
  - `format_score(s: Score) -> str`: one table row.

- [ ] **Step 1: Write failing tests:** a perfect match gives `off_path_nodes == 0`, `phase_agreement == 1.0` and `effect_recall == 1.0`. One extra node anchored in `app/unused.py` gives `off_path_nodes == 1`. Two expected phases merged into one actual phase give `phase_agreement` < 0.75. A missing span path raises `ValueError` from `load_expected`.
- [ ] **Step 2:** Run `pytest evals/tests -v` → FAIL.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Run → PASS.
- [ ] **Step 5: Commit** `feat(evals): expected format and scorer`.

### Task 2: codemap golden expected file and runner

**Files:**
- Create: `evals/codemap-trace.expected.json`, `evals/run_golden.py`, `evals/recordings/` (git-ignored except `.gitkeep`)
- Modify: `Makefile` (`eval` target)

**Interfaces:**
- Produces:
  - `run_golden(expected_path: Path, *, record: bool) -> Score`:
    1. Check that the repo HEAD equals `expected.commit`. If not, raise `RuntimeError` with both shas.
    2. Build the `Service` with `CachedModel(AnthropicModel, JsonFileCache(recordings/<name>.json))` when `record` is true, else with `ReplayOnlyModel`.
    3. Start the trace with `EntryCandidate(anchor=expected.entry, label="golden", reason="pinned")` and `mode="eager"`, wait, and score.
    4. Print `format_score`.
  - CLI: `python -m evals.run_golden evals/codemap-trace.expected.json [--record]`.

- [ ] **Step 1:** Pin the commit with `git rev-parse HEAD` and write it into the file, or leave `commit` empty to trace the working tree.
- [ ] **Step 2:** Read codemap's code: `cli/main.py`, `cli/trace.py`, `service.py`, `pipeline/run.py` and the `pipeline/*.py` stage modules. Write the expected phases, steps, spans and effects from the code only. Where the docs and the code disagree, follow the code and add a `"note"` field.
- [ ] **Step 3: Stop for user review** of `codemap-trace.expected.json`. Do not continue until the user approves it.
- [ ] **Step 4:** Run `python -m evals.run_golden evals/codemap-trace.expected.json --record` with the configured model. Save the score to `docs/notes/eval-results.md` with the date, model id, cost and wall time.
- [ ] **Step 5:** Run it again without `--record` and confirm the score is identical (replay works, no API calls).
- [ ] **Step 6: Commit** `feat(evals): codemap golden trace and runner` (the expected file, the runner and the results note; recordings stay out of git).

### Task 3: Verifier hop set and eval

**Files:**
- Create: `evals/hops/hops.json`, `evals/run_verifier.py`
- Test: `evals/tests/test_hops_file.py`

**Interfaces:**
- Produces:
  - `hops.json` entries: `{repo, caller: Anchor, callee: Anchor, kind, wiring: Anchor | null, real: bool, note}`. At least 30 entries. At least 20 must be real indirect hops taken from the target repos: string dispatch, registries and handlers, decorators and routes, DI. At least 10 must be planted fakes: the right caller with a plausible but wrong callee in the same repo.
  - `run_verifier(path: Path, *, record: bool) -> VerifierScore` with `VerifierScore(real_rejected: int, real_total: int, fake_caught: int, fake_total: int, unsure: int)`. It calls `verify_hop` (Plan 1 Task 10) once for each entry, and it hashes anchors at load time.
  - Pass bar: `real_rejected / real_total ≤ 0.02`. Report `fake_caught` without a pass bar.

- [ ] **Step 1: Write failing test:** `test_hops_file_valid` checks that every anchor passes `check_anchor` in its repo, that there are ≥20 real and ≥10 fake entries, and that no two entries are duplicates.
- [ ] **Step 2:** Run → FAIL (no file).
- [ ] **Step 3:** Build `hops.json` by reading the target repos. Write the runner.
- [ ] **Step 4:** Run → PASS. Then run `python -m evals.run_verifier evals/hops/hops.json --record`. Record the result in `docs/notes/eval-results.md`. If the pass bar fails, report it to the user with the rejected real hops listed. Do not tune the bar.
- [ ] **Step 5: Commit** `feat(evals): verifier hop set and eval`.

### Task 4: Scale smoke runs on all target repos

**Files:**
- Create: `evals/run_smoke.py`, `evals/smoke.json` (one question + entry per repo, chosen by reading each repo)

**Interfaces:**
- Produces: `run_smoke(path: Path) -> list[SmokeRow]` with `SmokeRow(repo, status, phases, steps, hops, cost_usd, wall_s, files_read)`. `files_read` counts the distinct paths in `read_file` calls, taken from the trace's `step_started`/`hop_found` events or from a counter on `RepoTools`; the builder adds a `RepoTools.files_read: set[str]` attribute for this.

- [ ] **Step 1:** For each repo (codemap, the sample fixture), read the code and choose one real system and its entry point. Write `smoke.json`.
- [ ] **Step 2:** Run `python -m evals.run_smoke evals/smoke.json` with the real model. Write the table to `docs/notes/eval-results.md`.
- [ ] **Step 3:** Report to the user: any `partial` caused by limits, cost per trace, and wall time per trace. They decide whether the defaults in `Settings` change, and whether subagent delegation (parked) needs to come back.
- [ ] **Step 4: Commit** `feat(evals): scale smoke runs`.
