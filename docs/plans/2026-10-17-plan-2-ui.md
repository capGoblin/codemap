# codemap v2 — Plan 2: Server + Canvas UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `codemap trace` and `codemap open` open a local browser canvas. Phases expand in place with the camera zoomed onto them. A detail panel, effect chips, an effect lane and filters complete the view. Everything ships inside the Python wheel.

**Architecture:** A thin FastAPI server under `/api/v1` calls only `service.py` (Plan 1 Task 13). A Vite + React + TS SPA uses `@xyflow/react` for drawing and `elkjs` for nested layout. One zustand store holds the shared UI state. TS types are generated from the server's OpenAPI. The built SPA is copied into `src/codemap/server/static/` by a hatch build hook.

**Tech Stack:** FastAPI, uvicorn, sse-starlette; Node 20 (dev/build only), Vite, React 18, TypeScript, @xyflow/react 12, elkjs, zustand, openapi-typescript, vitest, @testing-library/react, Playwright.

**Spec:** `docs/specs/2026-10-17-codemap-v2-design.md` (§9, §12). Mockups approved in brainstorming: zoom-in expand, DB/effect lane, side-effects screen.

**Depends on:** Plan 1 complete (`Service` API, domain models).

## Global Constraints

- Server binds `127.0.0.1` only, on a free port. API under `/api/v1`. No business logic in `server/`.
- `server` imports only `codemap.service`, `codemap.domain`, `codemap.settings`. Add `server` beside `cli` in the import-linter `layers` contract.
- Expand behaviour: a phase opens **in place**, the rest moves to make room, and the camera zooms onto it. No breadcrumb, no separate screen.
- Toolbar: **Expand all**, **Collapse all**, **Fit**, plus category filters.
- Effect categories and labels, one colour each, used everywhere: DB (`db`), Object store (`object_store`), Queue/Workflow (`queue`, `workflow`), Cache (`cache`), File (`file`), External call (`http`, `other`). Op letters: `W` write, `R` read, `D` delete, `P` publish/consume, `C` call.
- Node chips: op first, at most 3, then `+N`.
- `error` and `branch` edges and their nodes are drawn dimmed. The main path is drawn solid.
- No "from code / inferred" tag, no verdict marker, no effect matrix view.
- Layout engine: elkjs only (dagre is not allowed).

## Review Focus

1. **Trace still running when the page opens** → the canvas shows phases as they arrive (refetch on `phase_split` and `finished` events) and a progress strip with the latest event message. (Task 7)
2. **Partial or failed trace** → a visible banner with the status and the last warning; the canvas still renders what exists. (Task 7)
3. **Stale nodes** → a stale node shows a "code changed" mark and its detail panel says the snippet may not match. (Task 4, Task 5)
4. **Large flows (≥40 phases, ≥300 steps after Expand all)** → layout finishes under 2 s and the page stays responsive. Layout runs in a Web Worker. (Task 3)
5. **Lazy expand on a phase whose build fails** → the phase shows an error state with a retry; other phases keep working. (Task 7)

### Task 1: API server

**Files:**
- Create: `src/codemap/server/app.py`, `routes.py`, `sse.py`, `schemas.py`, `run.py`
- Modify: `.importlinter`, `pyproject.toml` (deps)
- Test: `tests/server/test_api.py` (FastAPI `TestClient`; `Service` built on the fixture repo with ScriptedModel after one finished trace)

**Interfaces:**
- Consumes: `Service` methods (Plan 1 Task 13), domain models.
- Produces:
  - `create_app(service: Service, static_dir: Path | None) -> FastAPI`.
  - Routes:
    - `GET /api/v1/health` → `{"version": str}`
    - `GET /api/v1/traces` → `list[Trace]`
    - `GET /api/v1/traces/{id}?depth=1` → `TraceGraph` (404 unknown id)
    - `GET /api/v1/traces/{id}/events?after=0` → SSE. Each message is `id: <event id>`, `event: <kind>`, `data: <Event JSON>`. The server polls `service.events` every 0.25 s and closes after `finished`. It honours the `Last-Event-ID` header.
    - `POST /api/v1/traces/{id}/nodes/{node_id}/expand` → `TraceGraph` (409 if the trace mode is not `lazy` and the node already has children)
    - `GET /api/v1/traces/{id}/nodes/{node_id}/detail` → `list[FunctionDetail]`
  - Static: serve `static_dir` at `/`, with SPA fallback to `index.html` for non-`/api` paths.
  - `server/run.py`: `serve_in_background(service: Service) -> str` starts uvicorn in a daemon thread on `127.0.0.1` and a free port, waits until `/api/v1/health` answers, and returns the base URL.
  - `GET /api/v1/openapi.json` is FastAPI's schema at that path.

### Task 3: Visible graph and ELK layout (pure, worker)

**Files:**
- Create: `frontend/src/graph/visible.ts`, `layout.ts`, `layout.worker.ts`
- Test: `frontend/tests/visible.test.ts`, `layout.test.ts`

**Interfaces:**
- Consumes: `TraceGraph` type.
- Produces:
  - `type VisibleNode = { id: string; kind: "phase" | "step"; parentId?: string; open: boolean; dimmed: boolean; node: Node }`; `type VisibleEdge = { id: string; source: string; target: string; kind: EdgeKind; dimmed: boolean }`.
  - `buildVisible(graph: TraceGraph, openIds: Set<string>): { nodes: VisibleNode[]; edges: VisibleEdge[] }`. Rules:
    - Phases are always visible. Steps are visible only when their parent is open.
    - An edge whose endpoint is a hidden step is rerouted to that step's parent phase. Rerouted duplicates are removed.
    - `dimmed` is true for `error`/`branch` edges and for nodes whose only incoming edges are `error`/`branch`.
    - Parents come before children in the array (React Flow requirement).
  - `layout(v): Promise<Map<string, {x: number; y: number; width: number; height: number}>>`. It builds an ELK graph with open phases as compound nodes holding their steps. Options: `elk.algorithm: layered`, `elk.direction: RIGHT`, `elk.hierarchyHandling: INCLUDE_CHILDREN`, `elk.layered.spacing.nodeNodeBetweenLayers: 60`. Child positions are relative to the parent. Fixed sizes: phase closed 220×110, step 180×90. Steps with the same `parallel_group` sit in the same layer.
  - `layout.worker.ts` runs `layout` in a Web Worker. `layoutInWorker(v)` has the same signature.

- [ ] **Step 1: Write failing tests:**
  - `visible`: closed phases → no steps, and the edge from step `s1` (in P1) to phase P2 is rerouted to P1→P2 once. Opening P1 → its steps appear after P1 in the array. An `error` edge is `dimmed`.
  - `layout` (elkjs in Node): two closed phases → P2.x > P1.x. Opening P1 → P1.width > 220 and P2.x is larger than before. A 40-phase × 8-step graph with all open lays out in < 2000 ms.
- [ ] **Step 2:** Run `npm --prefix frontend test` → FAIL.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Run → PASS.
- [ ] **Step 5: Commit** `feat(ui): visible graph rules and nested ELK layout`.

- Create: `frontend/src/canvas/FlowCanvas.tsx`, `PhaseNode.tsx`, `StepNode.tsx`, `edges.tsx`, `frontend/src/effects/EffectChip.tsx`, `frontend/src/Toolbar.tsx`, `frontend/src/App.tsx` (route `/traces/:id`)
- Test: `frontend/tests/canvas.test.tsx` (testing-library)

**Interfaces:**
- Consumes: `buildVisible`, `layoutInWorker`, store, `chipsFor`, `opLetter`, client.
- Produces the approved behaviour:
  - **Phase card:** title, `input → output`, chips (`EffectChip` shows op letter and target, coloured by category), `+N`, an open/closed caret, and a "code changed" mark when `stale`.
  - **Open phase:** a compound box with its steps inside.
  - **Step card:** title, `input → output`, chips.
  - **Clicks:** clicking a phase toggles it open. Clicking a step selects it, which opens the detail panel in Task 6. Clicking a chip selects its target.
  - **Edges:** `call` is solid, `async` is dashed purple with a small "async" label, and `error`/`branch` are dimmed. A dimmed node has opacity 0.35.
  - **Layout changes:** each change of `openIds` or graph re-runs the layout and animates nodes to their new positions (CSS transform transition 250 ms). When `focusNodeId` is set, call `fitView({ nodes: [{ id }], padding: 0.25, duration: 400 })` after layout. Expand all and Fit call `fitView({ duration: 400 })`.
  - **Selected effect target:** nodes not in `nodesTouching` fade to 0.3.
  - **Toolbar:** Expand all, Collapse all, Fit, and one toggle chip per `UiCategory` (crossed out when hidden).
