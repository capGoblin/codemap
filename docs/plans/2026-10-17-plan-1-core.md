# codemap v2 — Plan 1: Core (trace pipeline + CLI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `codemap trace "<question>"` resolves entry points, asks the user to confirm one, traces the real path with a verifier agent, splits it into phases and steps, validates, and stores the graph in SQLite. `codemap trace --json` prints it.

**Architecture:** Pure `domain` models and rules. Generic `agents` tool loop on the Anthropic SDK pointed at MiniMax M3. Sandboxed read-only `repo` tools. SQLite `store`. Fixed-step `pipeline`. One `service.py` facade used by a Typer CLI. Plan 2 adds the server and UI on top of `service.py`. Plan 3 adds evals.

**Tech Stack:** Python ≥3.12, uv, hatchling, pydantic v2, pydantic-settings, anthropic SDK, typer, rich, pathspec, tree-sitter-language-pack, platformdirs, pytest, ruff, mypy, import-linter. ripgrep (optional binary).

**Spec:** `docs/specs/2026-10-17-codemap-v2-design.md`

## Global Constraints

- Package name `codemap`, CLI entry `codemap = "codemap.cli.main:app"`, source in `src/codemap/`.
- Model: MiniMax M3 only, through the Anthropic-compatible endpoint. Env: `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `CODEMAP_MODEL` (default constant `DEFAULT_MODEL` in `settings.py`; the builder sets it to the exact M3 model id found in Task 6).
- No LangChain, LangGraph or deepagents.
- Agent tools are read-only, sandboxed to the repo root, no shell.
- Storage: `<repo>/.codemap/codemap.db`. Add `.codemap/` to `<repo>/.git/info/exclude`, never to `.gitignore`.
- Never store source code copies, file contents, API keys or tokens in the DB or logs.
- Layers: `cli, server → service → pipeline → domain, agents, repo, store`. `domain` imports nothing from codemap. `agents` imports nothing from codemap.
- Hop rule: recall first. Code never drops a hop alone. Only a verifier `rejected` verdict **with evidence** drops a hop.
- Effect categories: `db, object_store, queue, cache, file, workflow, http, other`. Ops: `read, write, delete, publish, consume, call`. Edge kinds: `call, async, error, branch`.
- Trace statuses: `running, complete, partial, failed`. Modes: `eager, lazy`.
- A limit hit ends the run `partial` with found work kept.
- Code style: small files, one concern each, small functions, standard idioms.

## Review Focus

1. **Free text that matches nothing** → `codemap trace` prints "no entry point found", exits 1, creates no trace row. (Task 11, Task 13)
2. **Model returns paths outside the repo** (`../x`, absolute path, symlink out) → the tool returns an error string; the anchor is rejected; nothing outside the root is read. (Task 4)
3. **Target folder is not a git repo** → trace has `commit_sha = None`, `dirty = False`; the exclude step is skipped without error. (Task 12)
4. **Model endpoint fails mid-trace** (429/5xx/timeout after retries) → trace ends `partial` with hops found so far stored; no traceback to the user. (Task 7, Task 12)
5. **Huge, minified or binary files** → `read_file` returns one page (400 lines) and tells the agent the next `start` line, so the agent can read the whole file page by page; lines over 2,000 chars (minified code) are cut; binary files return "binary file, not shown". (Task 4)

### Task 12: Walk, split, detail, validate, run

**Files:**
- Create: `src/codemap/pipeline/walk.py`, `split.py`, `detail.py`, `validate.py`, `run.py`
- Test: `tests/pipeline/test_walk.py`, `test_split.py`, `test_detail.py`, `test_validate.py`, `test_run.py`

**Interfaces:**
- Consumes: everything above.
- Produces:
  - `walk.py`:
    - `class HopInput(BaseModel)`: `caller: Anchor`, `callee: Anchor`, `kind: EdgeKind`, `hop_type: HopType`, `wiring: Anchor | None = None`.
    - `class EffectInput(BaseModel)`: the `Effect` fields.
    - `class WalkSubmit(BaseModel)`: `done: bool`, `notes: str = ""`.
    - `@dataclass WalkResult(hops: list[Hop], effects: list[Effect], partial_reason: str | None)`.
    - `walk_path(ctx, entry: Anchor, question: str) -> WalkResult`.
    - The `record_hop` handler does this:
      1. Run `check_anchor` on caller and callee. On failure, return the error text and record nothing.
      2. Hash both anchors.
      3. If `hop_type == "direct"` and `callee_named_in(caller range text, callee.symbol)`, set verdict `code_checked`.
      4. Else set `hop_type = "indirect"` and call `verify_hop`.
      5. Store the hop and emit `hop_found` / `hop_verified`.
      6. Return `"recorded"`, or for `rejected`: `"rejected: {evidence}; suggested callee: {anchor or none}"`.
      7. After `settings.max_hops` hops, return `"hop limit reached; call submit"`.
    - The `record_effect` handler checks the anchor and stores the effect.
    - `LimitReached` or `ModelError` → return the result so far with `partial_reason` set.
  - `split.py`:
    - `class PhaseDraft(BaseModel)`: `title`, `does`, `input`, `output`, `boundary_reason`, `start: int`, `end: int` (inclusive indices into `path_points`).
    - `class PhasesSubmit(BaseModel)`: `phases: list[PhaseDraft]`. Validator: spans are contiguous, cover `0..n-1`, and do not overlap. The loop's validation retry sends errors back.
    - `class StepDraft(BaseModel)`: `title`, `does`, `input`, `output`, `boundary_reason`, `anchors: list[Anchor]`, `parallel_group: int | None = None`.
    - `class StepsSubmit(BaseModel)`: `steps: list[StepDraft]`.
    - `split_phases(ctx, question, points: list[Anchor]) -> list[Node]`: builds level-0 nodes. Each phase gets `anchors=points[start..end]` and `effects` from `assign_effects` over the walk effects. The model never sets anchors or effects for phases.
    - `split_steps(ctx, phase: Node, effects: list[Effect]) -> list[Node]`: drops any step anchor not contained in one of the phase's anchors (`anchor_contains`). A step left with no anchors is dropped. Effects come from `assign_effects`.
    - `steps_edges(steps) -> list[Edge]`: consecutive `call` edges; members of one `parallel_group` all connect from the previous step and to the next step.
    - `phase_edges(phases, hops) -> list[Edge]`: `async` when any hop crossing from phase i to phase i+1 has `kind == "async"`, else `call`.
    - Each side hop (error or branch) becomes a level-0 or level-1 side node with one anchor (`title = callee.symbol`), attached by an `error`/`branch` edge to the node that contains its caller.
  - `detail.py`: `build_detail(tools: RepoTools, node: Node, hops: list[Hop]) -> list[FunctionDetail]`. One entry per anchor. `signature` comes from `outline` (the symbol whose range contains the anchor start). `code` is the anchor's full lines from `file_text`, with no cap. `calls` lists the callee symbols of hops whose caller equals this anchor. Code only, no model.
  - `validate.py`:
    - `@dataclass ValidationReport(nodes: list[Node], edges: list[Edge], warnings: list[str], dropped: int)`.
    - `validate_graph(tools, nodes, edges, points) -> ValidationReport`. It re-checks every anchor (`check_anchor`) and every effect anchor, and drops nodes with no valid anchors on `points` (`anchor_contains` against any point). It drops edges to dropped nodes. For phases with steps, it sets phase `effects = rollup_effects(steps)` and appends `io_chain_warning` results to `warnings`.
    - `PARTIAL_DROP_RATIO = 0.3`.
  - `run.py`:
    - `run_trace(ctx, question: str, entry: Anchor, mode: TraceMode) -> TraceStatus`. Steps, each emitting `step_started`:
      1. Walk.
      2. `path_points`.
      3. `split_phases`.
      4. If eager, `split_steps` for each phase on a `ThreadPoolExecutor(settings.split_concurrency)`.
      5. Validate.
      6. Save hops, walk effects and nodes.
      7. Set totals and status.
    - Events: `phase_split` after steps 3 and 4 (one per phase, `data={"phase_id": ...}`), and one `warning` event for each validation warning.
    - Status rules: `partial` if the walk has `partial_reason`, or `drop_ratio > PARTIAL_DROP_RATIO`, or any split hit a limit. `failed` only when no phase survives. Otherwise `complete`. Emits `finished`.
    - `expand_phase(ctx, phase_id: str) -> list[Node]`: lazy mode. Loads the phase (`get_node`), walk effects (`get_walk_effects`) and points (`path_points` over `get_hops`), runs `split_steps` and `validate_graph` for that phase, and calls `replace_children`.
